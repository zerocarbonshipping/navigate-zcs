Session 5: Build your own case#

This part of the workshop needs Navigate installed on your own machine. If you have not set that up yet, follow the installation steps in the README first.

Some of the decks in this repository and part of this workshop were written with the help of an AI coding assistant. You can do the same: describe the case you want and let the assistant write a first-shot deck.

This session is about prompting and create your personalized Navigate simulation from scratch. The new simulation will be saved under simulations/user/.

Read this before you use any of it

A prompt gets you a structure, not an answer. What comes back will run, and running is the easy part. Whether it means anything is on you. Each prompt below was tested by handing it to an AI assistant with no other instructions and running the deck it produced: all four ran without errors on the first attempt. But “it runs” is a statement about the syntax, not about the shipping.

Before you interpret a result:

Know where every input came from. Open the .inc files the assistant wrote and check the numbers. An assistant will happily produce a deck full of plausible numbers, and plausible numbers give plausible, but possibly wrong answers.

Most of the numbers in the assumption folder represent a world average, which is not always your case. For example, all 23 operational profiles in assumptions/defaults/installation/Route/ are defined per vessel class, not per geography: operational_profile_tanker_127k_dwt carries the speeds, time at sea and laden/ballast split of the world’s Suezmax fleet on average. None of them contains a distance at all, and the only two ports they know are port_global and port_europe that are abstractions for regulatory scope, not places on a map. So when your deck says “Ras Tanura to Ningbo”, those names and that distance are things you (or the AI assistant) should supply; keep in mind that the default operating pattern underneath is still a global average for the class (but you can change it for your case). The same goes for default fuel prices (fossil_fuel_oil_price_global), fleet age distributions, orderbooks, and feedstock availability.

So a case you build from scratch here is a structure to think with, not a study of a trade yet.

Start here: a prompt to write your prompt#

The prompts further down are long, because an AI assistant needs a lot of context to build a deck that works. You do not have to write that yourself. Describe your case in a few sentences, hand this short start-up prompt to your AI coding assistant, and let it write the full prompt for you. It checks your installation, reads the repository, asks you about whatever the library does not settle, and shows you the full prompt to approve before it builds anything.

Replace the text in square brackets with your own case:

I want to build and run a case with Navigate, the shipping decarbonisation model in this repository. Don't build anything yet: first, help me write a good prompt for it.

My case: [YOUR CASE, IN A FEW SENTENCES: which ships and how many (a market segment with many owners, so think in hundreds of ships rather than one company's fleet), the trade or the region, the years, which fuels can compete, which regulation applies, and the question you want answered.]

1. Check that Navigate is installed (README.md) and tell me what is missing. Don't install anything yourself.
2. Read docs/reference_manual/, the example decks in simulations/examples/ and the data library in assumptions/.
3. Use the library's values wherever it has them, and ask me, a few questions at a time, about the rest. Keep the deck small.
4. Write the full prompt you would want to be given, taking the prompts of docs/workshop/05-build-your-own-case.ipynb and the full prompt at the end of docs/workshop/01-run-a-simple-case.ipynb as models. Mark every number not from the library INVENTED, and have the deck built in a new folder, simulations/user/my_simulation/ (my_simulation_2, _3, ... if taken), without changing any existing file. Show it to me and wait for my OK.

For example, to get a case close to the first full prompt below, write as your case: “200 Suezmax crude tankers (about 127,000 DWT), owned by many companies, sail from Ras Tanura, Saudi Arabia, to Ningbo, China, laden out and in ballast home, from 2026 to 2050. They start on fuel oil and can switch to LNG, e-ammonia or e-methanol made in the Middle East. No regulation applies: I want to see what the model does when nothing pushes it.” Your answers to its questions decide the numbers, and so the results.

Four example full prompts#

We propose here four example full prompts that lead to a working Navigate deck. You can use them as reference when building your own case. Like pointing your AI assistant to one of them: “Take the prompt one trade, two ports as example and modify this, this and that…”

Each prompt starts with the same short HOW NAVIGATE WORKS block. It gives the assistant what it cannot guess: where the syntax and the data library live, how to run a deck, and where the results come out as numbers. Keep it when you write your own prompt. It is what lets any assistant (Claude, Copilot, ChatGPT, …) work from this repository.

1. One trade, two ports#

Example case with a trade route 200 Suezmax crude tankers (about 127,000 DWT), about a tenth of the world fleet of that class and owned by many companies, on one named route, from Ras Tanura in Saudi Arabia to Ningbo in China, sailing laden out and in ballast home. They start on fuel oil. LNG and fuel oil are bought on the world market, while e-ammonia and e-methanol can be made in the Middle East on dedicated solar and wind power. No regulation applies at all, so every fuel choice is made on cost alone: the case shows what the model does when nothing pushes it.

Ras Tanura to Ningbo: one route, Middle East e-fuels, no regulation.

You are helping me build a simulation deck for Navigate, the shipping
decarbonisation model in this repository. Write the files yourself; do not only
describe them.

  in docs/reference_manual/overview.md, and every node type (Fleet, Vessel, Route,
  Port, Fuel, Plant, Producer, Regulation, ...) has its own page in
  docs/reference_manual/.
- assumptions/ is the data library. `Load DefaultVoyage` reads the module file
  assumptions/modules/installation/default_voyage.inc. `Import Fleet "tanker_127k_dwt"`
  reads one node from assumptions/defaults/installation/Fleet/tanker_127k_dwt.inc.
- simulations/examples/example_1 to example_4 are complete decks that run.
- Run a deck from the repository root, in the Python environment where Navigate
  was installed from this repository, with:
      python -m navigate <path to the .nav file> -d ./assumptions
  (`python -m navigate` run from the repository root always uses this
  repository's code; the shorter `navigate` command may point to another copy.)
  Do not install or upgrade any package without asking me first.
- A run writes a .log file next to the .nav. The end of the .log has a "Log
  summary" table with the number of warnings and errors. Some warnings come
  with the library and are expected on any deck built from it (for example "No
  technology cost of capital supplied", "Does not have convex load functions",
  or a feedstock being over-used by a library producer): report them, but do
  not try to fix them. Add `Load DefaultPlot`
  to the .nav DEFINE block to also get the charts in plots/ and plots_analysis/.
  If you cannot run terminal commands, give me the exact command, wait for me to
  paste back the end of the output, and fix whatever it reports.
- To get results as numbers, add `Load DefaultReport` to the .nav DEFINE block.
  The run then also writes plots/<deck name>_report_default.xlsx. Its "Global"

  the fuel name is in the third header row) and the fleet's emissions

Build it in a new folder, simulations/user/gulf_asia_tanker/, with the .nav file
gulf_asia_tanker.nav and its .inc files in includes/. If that folder already exists,
use gulf_asia_tanker_2 (then _3, ...) instead, and tell me which. Write nothing outside
that folder: do not change, move or delete any file already in the repository.

THE CASE
- Fleet: Suezmax-class crude tankers, ~127,000 DWT, on a single trade
- Trade: Ras Tanura (Saudi Arabia) to Ningbo (China), laden out, ballast home
- Fuels: fuel oil and LNG as global commodities, plus e-ammonia and e-methanol
  produced in the Middle East on dedicated renewables
- Regulation: none. Neither port is in the EU. That is the point of the case:
  I want to see what the model does when nothing is pushing it.

- Fleet size: 200 ships to start with (INVENTED: about 9 % of the library's
  2,255 Suezmax tankers, a market segment with many owners rather than one
  company's fleet; the library's own fleet size for this class is the whole

replace at end of life, or keep burning oil.

HOW TO BUILD IT
- Build your own Fleet node from the library's Vessel files with Copy Vessel, as
  simulations/examples/example_4/includes/fleet.inc does. Import Fleet would bring
  the world fleet, with a world-sized fleet and orderbook.
- The library's operational profile is a world-average pattern between two
  abstract ports (port_global, port_europe). Do not use those ports: build a
  ROUND_TRIP route between the two named ports, taking speeds and time in port
  from the profile's own values, as example_4's route.inc does (its comments show
  the arithmetic). Use a realistic sea distance and mark it INVENTED.
- Rebuild the other parts example_4 has, with this case's own values: the ports,
  the bunker logistics (how fuel travels from the plants to each port) and the
  regions (where the fuels are made).
- Give the fuel producers a share of the library's global feedstock ceilings,
  marked INVENTED, as example_4's producer.inc does.
- Energy-efficiency technologies are optional here: leave them out.

NUMBERS
Every number must come from assumptions/ and be referenced by name
(Forecast("..."), Curve("..."), Variable("...")), never copied in as a literal.
Where the library itself stores a plain number (the fuel-conversion costs in a
Fleet file, the time at sea in a Route file), copy it with a comment naming the
file it came from.
The library already covers this vessel class - use its own values:
    assumptions/defaults/installation/Fleet/tanker_127k_dwt.inc
    assumptions/defaults/installation/Route/operational_profile_tanker_127k_dwt.inc
Take structure from simulations/examples/example_4/ and none of its numbers.
Anything the library genuinely lacks - port-to-port distance or the bunker
transport cost, for instance - mark INVENTED in a comment where it appears and
list them in the .nav header. BunkerLogistics takes its distances and transport
cost as plain numbers, not as Variables.

DECK RULES
The .nav DEFINE and EVENTS blocks accept only Include and Load. Every node
declaration, Import and Copy goes in an .inc file that they include.

BEFORE YOU TELL ME IT WORKS
Run it (or have me run it) as above. Report the exit code and the warning count
from the Log summary. Tell me the fuel mix in the first year and the last, from
the report, and say plainly whether anything actually switched.

The same trade twice, to isolate the owners’ choices. No specific geography: one route that you choose, sailed by two fleets of the same vessel class in the same market, with the same costs, the same fuels and the same regulation. Fleet A fits no energy-efficiency measure. Fleet B fits the technologies the library offers for that class (hull coatings, propeller devices, rotor sails, air lubrication and so on). Whatever separates the two fleets by 2050 (fuel mix, emissions, freight rate, fuel and compliance bill) comes from that one difference.

One route, two fleets: the only difference is what Fleet B fits.

4. A global study: the cost of waiting#

A policy question on the Center’s example scenario. The mid-regulation reference scenario includes a global fuel standard (gfs): a well-to-wake intensity limit that every ship is held to worldwide, tightening from 2028 to 2050. What if it started five years late, but kept the same 2050 target? No deck to build from scratch here: the scenario is run twice, as it is and with every date before 2050 moved later, on the coarse time grid of Session 3 so each run takes a few minutes. The answer is one number worth remembering: the extra megatonnes of CO2e a delay costs, and whether the fleet catches up by 2050. The change goes in a copy of the regulation file, so the reference scenario itself stays untouched.

How it differs from the scenarios in the repository. The four reference scenarios in simulations/scenarios/ differ in how strict the regulation is: none at all, EU ETS and FuelEU only (business as usual), or those plus a global fuel standard that is moderate (mid) or strict (strong). Both standards start in 2028. This case keeps the mid scenario exactly as it is and changes only when its standard starts, which none of them explores. It also runs on the coarse grid, so compare its two runs with each other, not with the yearly results of Session 4.

The global fuel standard of the mid-regulation scenario (grey) and the same standard started five years later, with the same 2050 target (blue).

Running what you get#

In a terminal, in the Python environment where you installed Navigate, run from the repository root:

python -m navigate simulations/user/<your_case>/<your_case>.nav -d ./assumptions

Three things worth knowing:

  • python -m navigate from the repository root always runs this repository’s code. The shorter navigate simulations/... works too, but if another copy of Navigate is installed on your machine it may run that one instead, and fail on decks that are fine.

  • -d ./assumptions is needed whenever the deck uses Load, Import or Copy — which any deck built on the library does. A fully self-contained deck like the minimal single-vessel example of Tutorial 1 needs no -d at all.

  • Output lands next to the deck, not in your working directory. Navigate resolves the deck path first and writes everything relative to that.

Where the plots are#

Load DefaultPlot declares two Plot nodes, so a run fills two folders inside the deck’s own directory:

where

what is in it

<deck folder>/plots/

the headline set, nine charts — among them fuel consumed, absolute emissions, installed power, producer development

<deck folder>/plots_analysis/

the fuller set, thirty-two charts — among them fleet evolution and conversions, speeds, emission intensity, expenses, bunker price and supply per port, plant production costs

How many you get depends on what the deck contains. Two more files land beside them: <deck>.log, and plot_data.pkl, which holds the solved model.

Open the PNGs from the file browser, or in a notebook with from IPython.display import Image; display(Image(filename=...)). Which charts appear is set by the add_plot("...") calls in the deck; the full list of labels is in the appendix of the reference manual’s Plot page.

Old plots are not cleared

Navigate overwrites a chart it regenerates but never deletes one it no longer produces, so a PNG from an earlier configuration can sit in the folder looking exactly as current as the rest. Delete the folder before a re-run if you have changed which plots the deck asks for.

If the run finishes without errors, check the Log summary table at the foot of <deck>.log: it counts warnings and errors, and is the quickest way to tell a clean run from one that merely completed.
