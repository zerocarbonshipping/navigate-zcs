Session 1: Run a simple case#

Keep in mind that some of the data have been completely invented for the purpose of this exercise (so please do not create your own trade route based on this example).

We look at how Navigate would model the decisions of the shipowners and operators serving a line between San Antonio and Rotterdam, in a world getting towards decarbonisation: green fuels are starting to be produced at scale, technology options for engines and retrofits are available, and regulations incentivizing the use of green fuels are in place.

The case#

San Antonio to Rotterdam via the Panama Canal: the two bunker ports, the voyage, and the possible fuel plants.

The case follows the Panamax bulk carriers (~80,000 DWT) that carry copper concentrate from San Antonio, Chile to Rotterdam, roughly 7,600 nautical miles each way via the Panama Canal, returning in ballast (empty).

It is 2026: the segment counts 300 ships, and every one of them burns fuel oil. The fleet is ageing and most of it has to be renewed before 2050, the horizon of the simulation.

The ships are also exposed to two regulations: FuelEU Maritime and the EU ETS, both of which cover half of the voyage.

Navigate does not follow one specific company. It represents the whole segment as a single Fleet, whose decisions stand for those of the many shipowners and operators in it. Operators decide which fuel to bunker and where, and how fast to sail. Owners decide when to retrofit ships, order new ones and fit efficiency measures.

Four ship designs are available on the market:

Configuration

ship_oil

ship_lng

dual-fuel LNG

On the other side, we follow the behavior of two groups of fuel producers: producers of e-fuels (e-ammonia or e-methanol) and producers of biofuel (bio-methanol). The e-fuel plants can be installed in Chile or in Europe, the biofuel plants only in Europe (to simplify the case).

What you’ll do#

Run the case. Solve it once, from 2026 to 2050.

Read the results. The fleet’s emissions, the fuel it bunkers, and what moving the cargo costs.

Sensitivity analysis. Change some of the input parameters and see what happens.

How the deck is built, the data behind it and how the model reaches its answer are the subject of Session 2.

STEP 2: Run the case and see the results#

Run the next cell to solve the case once, from 2026 to 2050. It takes about twenty seconds. The results that we are plotting for this example are:

  • the fleet’s well-to-wake emissions over time;

  • the energy the fleet bunkers each year, by fuel. A dual-fuel ship that bunkers oil counts as oil here;

  • the instantaneous freight rate on the fleet: what the trade cost in that year, given the fuel prices and compliance bills that actually materialised.

These numbers are calculated before any redistribution mechanisms of the collected taxes, which are currently not modelled in Navigate.

# @title Run the case and see the results
import argparse
import contextlib
import io
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np
from navigate.manager import SimulationManager

NAV = Path("simulations/examples/example_4/example_4.nav")
ARGS = argparse.Namespace(data_dir=Path("./assumptions"), solver=None)

# One house style for every figure in the workshop. It lives in
# docs/workshop/_style.py rather than in this cell, so that the notebooks
# cannot drift apart - which is exactly what had happened. The
# colours are Navigate's own, and that file explains the one thing about them
# that surprises people: the hue says how a fuel was MADE, not which molecule it
# is, so bio-methanol and e-methanol are deliberately different colours.
import sys

_STYLE_DIR = str(Path("docs/workshop").resolve())
if _STYLE_DIR not in sys.path:
    sys.path.insert(0, _STYLE_DIR)

from _style import (AXIS, GRID, INK, SUBINK, TICK, fuel_colour, fuel_label,
                    fuel_sorted, scen_colour)


def run_case(tweak=None, quiet=True):
    """Parse the deck, optionally modify it, solve it, return the manager."""
    m = SimulationManager()
    ctx = contextlib.redirect_stdout(io.StringIO()) if quiet else contextlib.nullcontext()
    with ctx:
        m.read_deck(NAV, ARGS)
        if tweak is not None:
            tweak(m)
        m.run()
    return m


def years_of(m):
    return m.get_dateline().astype("datetime64[Y]").astype(int) + 1970


# one solve, 2026 to 2050: the reference every sensitivity is compared with
%time base = run_case()
YEARS = years_of(base)


# ===========================================================================
#  The machinery for the sensitivity analysis. Nothing to edit here - the
#  levers are further down.
# ===========================================================================
def scale(forecast_name, factor):
    """Multiply a forecast by `factor`, keeping what the deck already set.

    set_multiplier REPLACES the Multiplier rather than compounding with it, and
    several library forecasts ship a non-unity one - fuel_eu_target_reduction
    is 91.16. Writing the factor straight in would not scale that limit, it
    would delete it.
    """
    def tweak(m):
        f = m.nodes.forecasts[forecast_name]
        f.set_multiplier(f.get_multiplier() * float(factor))
    return tweak

def both(*tweaks):
    """Apply several levers to one freshly parsed deck."""
    def tweak(m):
        for t in tweaks:
            t(m)
    return tweak

def penalty(factor):
    """Scale the FuelEU non-compliance penalty.

    The base value is the library's own Variable("fuel_eu_remedial_cost"),
    read off the parsed deck rather than hardcoded, so this lever follows the
    assumptions library if it is ever revised. It is a Variable and not a
    Forecast, which is why it needs its own helper rather than scale().
    """
    def tweak(m):
        base_cost = m.nodes.variables["fuel_eu_remedial_cost"].get()
        m.nodes.regulations["fuel_eu"].set_remedial_cost(base_cost * factor)
    return tweak

def chile_in_scope(m):
    """Put San Antonio inside both schemes.

    With both ends of the voyage in the jurisdiction it becomes an *intra*
    voyage, so IntraFraction = 1 applies and the whole trip is counted - the
    honest way to model full coverage, rather than editing InterFraction.
    """
    for r in ("eu_ets", "fuel_eu"):
        m.nodes.regulations[r].jurisdiction = [m.nodes.ports["rotterdam"],
                                               m.nodes.ports["san_antonio"]]

def without_new_technology(m):
    """Freeze efficiency where the fleet already is: nothing more gets fitted.

    BOTH limits are needed - the retrofit limit alone still lets a measure
    arrive on a newbuild. Measures with an initial share keep it, they just
    never grow.
    """
    fleet = m.nodes.fleets["copper_trade"]
    for technology in fleet.technologies:
        fleet.set_retrofit_technology_limit(technology.get_name(), 0.)
        fleet.set_newbuild_technology_limit(technology.get_name(), 0.)

TARGET = "fuel_eu_target_reduction"
FOSSIL = {"fossil_fuel_oil", "liquefied_natural_gas"}

def summarise(m):
    """One solve, read the way notebook 3 reads its fleets."""
    fleet = m.nodes.fleets["copper_trade"]
    years = years_of(m)
    wtw = np.nan_to_num(np.asarray(
        fleet.profile.get_total_equivalent_WTW(), dtype=float))

    energy, by_year = {}, {}
    for fuel, series in fleet.profile.get_consumed_energy().items():
        values = np.nan_to_num(np.asarray(series, dtype=float))
        if values.sum() <= 0:
            continue
        energy[fuel] = float(values.sum())
        by_year[fuel] = values
    grand = sum(energy.values())
    last_all = sum(float(v[-1]) for v in by_year.values())
    last_alt = sum(float(v[-1]) for f, v in by_year.items() if f not in FOSSIL)

    return {"years": years,
            "wtw": wtw / 1e3,                                  # kt CO2e per year
            "mix": {k: 100. * v / grand for k, v in energy.items()},
            # PJ per year, stacked in Navigate's own fuel order
            "by_year": {f: by_year[f] / 1e6 for f in fuel_sorted(by_year)},
            # USD per THOUSAND cargo-miles, as everywhere else in the workshop
            "freight": 1e3 * np.asarray(
                fleet.profile.get_instantaneous_freight_rate(), dtype=float),
            "alt_last": 100. * last_alt / last_all if last_all else 0.}


# `base` is the run above and is already solved, so the reference
# costs nothing here - only your scenario is re-solved, once, below.
ref = summarise(base)

print(f"the reference, {YEARS[0]}-{YEARS[-1]}")
for _label, _value, _unit in (
        (f"well-to-wake in {YEARS[0]}", f"{ref['wtw'][0]:,.0f}", "kt CO2e/yr"),
        (f"well-to-wake in {YEARS[-1]}", f"{ref['wtw'][-1]:,.0f}", "kt CO2e/yr"),
        ("cumulative over the horizon", f"{ref['wtw'].sum():,.0f}", "kt CO2e"),
        (f"alternative fuels in {YEARS[-1]}", f"{ref['alt_last']:.1f}", "%"),
        (f"freight rate in {YEARS[-1]}", f"{ref['freight'][-1]:,.2f}",
         "USD per k cargo-mile")):
    print(f"  {_label:30} {_value:>9}  {_unit}")


def plot_cases(cases):
    """Emissions, the fuel bunkered and the freight rate, one line or panel per case.

    `cases` maps a label ("reference", "your scenario") to what summarise()
    returns. The same figure shows the reference on its own and the
    comparison with your scenario. It is drawn at the width the page shows it,
    so the type stays readable: emissions and cost on top, the fuel mix below."""
    from matplotlib.ticker import MaxNLocator

    order = list(cases)
    TITLE, LABEL, TICK_SIZE = 12.5, 10.5, 10

    fig = plt.figure(figsize=(11, 8.2), constrained_layout=True)
    grid = fig.add_gridspec(2, len(order), height_ratios=[1, 1.05])
    # top row: emissions and cost, each half the width whatever the number of cases
    top_grid = grid[0, :].subgridspec(1, 2, wspace=0.08)
    axE = fig.add_subplot(top_grid[0, 0])
    axC = fig.add_subplot(top_grid[0, 1])
    # bottom row: one fuel-mix panel per case, on a shared scale so they read
    # against each other
    mix_axes = [fig.add_subplot(grid[1, 0])]
    mix_axes += [fig.add_subplot(grid[1, k], sharex=mix_axes[0], sharey=mix_axes[0])
                 for k in range(1, len(order))]

    for s in order:
        axE.plot(cases[s]["years"], cases[s]["wtw"], lw=2.4, marker=".", ms=7,
                 label=s, color=scen_colour(s))
    axE.set_title("Well-to-wake emissions", fontsize=TITLE, color=INK, loc="left")
    axE.set_ylabel("kt CO2e per year", fontsize=LABEL, color=SUBINK)
    axE.set_ylim(bottom=0.)
    if len(order) > 1:
        axE.legend(fontsize=LABEL, frameon=False, labelcolor=SUBINK, loc="lower left")

    # the two end labels land within a few cents of each other, so push the
    # lower series' label below its point rather than letting them overlap
    _high = max(order, key=lambda s: cases[s]["freight"][-1])
    for s in order:
        axC.plot(cases[s]["years"], cases[s]["freight"], lw=2.4, marker=".", ms=7,
                 label=s, color=scen_colour(s))
        axC.annotate(f"{cases[s]['freight'][-1]:,.2f}",
                     (cases[s]["years"][-1], cases[s]["freight"][-1]),
                     xytext=(-4, 8 if s == _high else -16),
                     textcoords="offset points", ha="right",
                     fontsize=LABEL, color=scen_colour(s), fontweight="bold")
    axC.set_title("Freight rate: what moving the cargo cost", fontsize=TITLE,
                  color=INK, loc="left")
    axC.set_ylabel("USD per thousand cargo-miles", fontsize=LABEL, color=SUBINK)
    axC.set_ylim(bottom=0.)
    # The rate carries what the fleet pays out and almost nothing it gets back:
    # Navigate has no rebate or subsidy funded from what a regulator collects,
    # so a scheme that recycled its revenue would sit lower than this.
    axC.text(.03, .04,
             "Carbon and compliance payments are in this rate." + chr(10)
             + "None of what regulators collect is paid back:" + chr(10)
             + "the model has no rebate or subsidy funded from it.",
             transform=axC.transAxes, fontsize=8.5, color=SUBINK,
             va="bottom", ha="left", linespacing=1.5)

    fuels = fuel_sorted({f for c in cases.values() for f in c["by_year"]})
    for ax, s in zip(mix_axes, order):
        stack = [cases[s]["by_year"].get(f, np.zeros(len(cases[s]["years"])))
                 for f in fuels]
        ax.stackplot(cases[s]["years"], *stack,
                     colors=[fuel_colour(f) for f in fuels],
                     labels=[fuel_label(f) for f in fuels], linewidth=0, alpha=.9)
        ax.set_title(f"Fuel bunkered, {s}", fontsize=TITLE, color=INK, loc="left")
        ax.margins(x=0)
    mix_axes[0].set_ylabel("PJ per year", fontsize=LABEL, color=SUBINK)
    fig.legend(*mix_axes[0].get_legend_handles_labels(), fontsize=LABEL,
               frameon=False, labelcolor=SUBINK, ncol=len(fuels),
               loc="outside lower center")

    for ax in (axE, axC, *mix_axes):
        ax.xaxis.set_major_locator(MaxNLocator(integer=True))
        ax.grid(color=GRID, lw=.8)
        ax.set_axisbelow(True)
        ax.tick_params(colors=TICK, labelsize=TICK_SIZE, length=0)
        for side in ("top", "right"):
            ax.spines[side].set_visible(False)
        for side in ("left", "bottom"):
            ax.spines[side].set_color(AXIS)

    return fig


def run_your_scenario():
    """Solve the levers set in the YOUR SCENARIO cell and compare with the reference.

    Reads the lever names (OIL_PRICE ... FREEZE_EFFICIENCY) from the notebook
    when it is called, so the cell that sets them only has to call this.
    """
    MULTIPLIERS = [("OIL_PRICE", OIL_PRICE, "fossil_fuel_oil_price_global"),
                   ("GAS_PRICE", GAS_PRICE,
                    "liquefied_natural_gas_price_global"),
                   ("CARBON_PRICE", CARBON_PRICE, "eu_ets_carbon_credit_price"),
                   ("FUELEU_TARGET", FUELEU_TARGET, TARGET),
                   ("CHILEAN_POWER", CHILEAN_POWER, "electricity_cost_americas_mid"),
                   ("EUROPEAN_POWER", EUROPEAN_POWER, "electricity_cost_europe_mid"),
                   ("BIOMASS", BIOMASS,
                    "feedstock_biomethanol_gasification_availability"),
                   ("BIOGENIC_CO2", BIOGENIC_CO2, "carbon_dioxide_biogenic_availability"),
                   ("TRADE_GROWTH", TRADE_GROWTH, "trade_growth_bulk_carrier")]

    # Trade is compounded as log(1 + growth), so a year shrinking by 100 % or more has
    # no meaning - say so here rather than let the solve fail on it.
    _growth = base.nodes.forecasts["trade_growth_bulk_carrier"]
    if min(TRADE_GROWTH * _growth.calculate(_d) for _d in base.get_timeline()) <= -1.:
        raise ValueError(f"TRADE_GROWTH = {TRADE_GROWTH} would make trade shrink by 100 % "
                         "or more in a year. Pick a value closer to zero.")

    CHANGED = [(n, v) for n, v, _ in MULTIPLIERS if v != 1.0]
    TWEAKS = [scale(t, v) for n, v, t in MULTIPLIERS if v != 1.0]
    if FUELEU_PENALTY != 1.0:
        CHANGED.append(("FUELEU_PENALTY", FUELEU_PENALTY))
        TWEAKS.append(penalty(FUELEU_PENALTY))
    if FULL_COVERAGE:
        CHANGED.append(("FULL_COVERAGE", True))
        TWEAKS.append(chile_in_scope)
    if FREEZE_EFFICIENCY:
        CHANGED.append(("FREEZE_EFFICIENCY", True))
        TWEAKS.append(without_new_technology)

    if not TWEAKS:
        print("Every lever is still at its reference, so this would just re-solve it.")
        print("Change one of the numbers above and run this cell again.")
    else:
        print("solving your scenario:")
        for _name, _value in CHANGED:
            print(f"  {_name:16} {_value}")
        yours = run_case(both(*TWEAKS))
        you = summarise(yours)

        print(f"{chr(10)}  {'':32} {'reference':>11} {'yours':>11} {'change':>13}")
        for _label, _r, _y, _fmt, _pp in (
                (f"well-to-wake in {YEARS[-1]}, kt/yr",
                 ref["wtw"][-1], you["wtw"][-1], ",.0f", False),
                ("cumulative, kt", ref["wtw"].sum(), you["wtw"].sum(), ",.0f", False),
                # a share is already a percentage, so it moves in POINTS, not per cent
                (f"alternative fuels in {YEARS[-1]}, %",
                 ref["alt_last"], you["alt_last"], ".1f", True),
                (f"freight rate in {YEARS[-1]}, USD/k mile",
                 ref["freight"][-1], you["freight"][-1], ",.2f", False)):
            _change = (f"{_y - _r:+.1f} pp" if _pp
                       else f"{100. * (_y / _r - 1.):+.1f} %")
            print(f"  {_label:32} {_r:11{_fmt}} {_y:11{_fmt}} {_change:>13}")

        fig = plot_cases({"reference": ref, "your scenario": you})
        fig.suptitle("  " + ",  ".join(f"{n} x {v}" for n, v in CHANGED),
                     fontsize=11, color=SUBINK, x=0.01, ha="left")
        plt.show()

        print("what moved most, in percentage points of the fuel mix:")
        _delta = sorted(((you["mix"].get(f, 0.) - ref["mix"].get(f, 0.), f)
                         for f in set(ref["mix"]) | set(you["mix"])),
                        key=lambda d: -abs(d[0]))
        for _d, _f in _delta[:5]:
            print(f"  {fuel_label(_f):20} {_d:+6.1f} pp")


plot_cases({"reference": ref})
plt.show()

STEP 3: Sensitivity analysis#

Change some of the input values of the “reference scenario” to see what changes in the results.

All levers that we prepared can be changed with multipliers, except two that can be used as switches:

  • FULL_COVERAGE puts San Antonio inside both regulatory schemes.

  • FREEZE_EFFICIENCY stops anything further being fitted, on newbuilds as well as on retrofits.

GAME: Find out which scenario (realistic?) leads to the lowest emissions and transport costs by 2050!

Advanced sensitivities#

The levers proposed in the previous section are just a simple example of what can be changed in the model.

Advanced sensitivities changing other parameters or personalized simulations can be done by:

  • editing the deck in simulations/examples/example_4/ itself (needs a local installation)

  • building a new case from scratch as Session 5 describes (needs a local installation)

  • you can also check out our Horizon-zcs tool on GitHub for global sensitivity analysis (which is what we are using for our own analyses)

Regenerate this case yourself#

You can rebuild the case of this session, and run it once, by handing a prompt to an AI coding assistant (Claude, Copilot, ChatGPT, …).

This needs Navigate installed on your own machine: follow the installation steps in the README, or the more detailed Getting started tutorial. If it is not installed yet, either prompt will also help you install it.

A prompt to write a well-functioning Navigate prompt#

This is an example prompt that can be used to write another, “full” prompt which, when executed by an AI coding assistant, builds a well-functioning deck reproducing the case of Session 1. This start-up prompt checks your installation, reads the repository, asks you about the numbers and choices the library does not settle, and writes the full prompt for you to approve. It takes the full prompt below as its model, so it starts from the same numbers; any number you change in your answers changes the results.

I want to build and run a case with Navigate, the shipping decarbonisation model in this repository. Don't build anything yet: first, help me write a good prompt for it.

The case: 300 Panamax bulk carriers (about 80,000 DWT) carry copper concentrate from San Antonio, Chile, to Rotterdam via the Panama Canal, loaded out and empty back, from 2026 to 2050. In 2026 they all burn fuel oil. They can switch to LNG, methanol or ammonia ships, and fit efficiency measures. E-methanol and e-ammonia can be made in Chile or in Europe, bio-methanol only in Europe. EU ETS and FuelEU Maritime cover half of the voyage. One run, no sensitivities.

1. Check that Navigate is installed (README.md) and tell me what is missing. Don't install anything yourself.
2. Read docs/reference_manual/, the example decks in simulations/examples/ (not example_4: it is this case, already built) and the data library in assumptions/.
3. Use the library's values wherever it has them, and ask me, a few questions at a time, about the rest. Keep the deck small.
4. Write the full prompt you would want to be given, taking the full prompt at the end of docs/workshop/01-run-a-simple-case.ipynb and the prompts of docs/workshop/05-build-your-own-case.ipynb as models. Mark every number not from the library INVENTED, and have the deck built in a new folder, simulations/user/my_simulation/ (my_simulation_2, _3, ... if taken), without changing any existing file. Show it to me and wait for my OK.

The full prompt#

After running the start-up prompt, the AI assistant should have suggested a more elaborate prompt which, when executed, leads to a well-functioning Navigate simulation that matches your case description. The full prompt below was tested by handing it to two Claude models (Opus and Sonnet) with no other instructions: both decks ran without warnings or errors, and both came within 0.2 % of the results above.

You are helping me build and run a simulation deck for Navigate, the shipping decarbonisation model in this repository. Write the files yourself; do not only describe them.

GETTING NAVIGATE RUNNING (do this first)
- Navigate is the repository https://github.com/zerocarbonshipping/navigate-zcs.
  If it is not on this machine yet, tell me, and propose cloning it (or
  downloading the zip from GitHub). Work from the repository root from then on.
- Check whether Navigate is installed, from the repository root:
      python -m pip show navigate-zcs
      python -m navigate --help
  If both work, go on to the deck.
- If not, the installation steps are in README.md (section "Installation"):
  Python 3.12, ideally in its own environment (venv or conda), then
      python -m pip install .
  from the repository root. The README also has the fixes for the two common
  Windows errors (PowerShell refusing to activate a venv, and pip.exe "Access is
  denied"). A slower, beginner's walk-through with VS Code is in
  docs/tutorials/getting_started.md, also online at
  https://zerocarbonshipping.github.io/navigate-zcs/tutorials/getting_started.html
- Show me the commands and wait for my go-ahead before you install, upgrade or
  create anything. No extra solver is needed: Navigate comes with HiGHS. Skip the
  optional Gurobi extra unless I say I have a full Gurobi licence.

HOW NAVIGATE WORKS (read this before writing anything)
- A deck is one .nav file plus the .inc files it includes. The syntax is explained
  in docs/reference_manual/overview.md, and every node type (Fleet, Vessel, Route,
  Port, Fuel, Plant, Producer, Regulation, ...) has its own page in
  docs/reference_manual/.
- assumptions/ is the data library. `Load DefaultCalibration` reads the module file
  assumptions/modules/installation/default_calibration.inc. `Import Fuel "methanol_bio"`
  reads one node from assumptions/defaults/installation/Fuel/methanol_bio.inc.
  `Copy Vessel "a" "b"` imports node "a" from the library under the new name "b".
- simulations/examples/example_1 to example_3 are complete decks that run: read
  them for syntax. Do NOT open simulations/examples/example_4/, and leave it out
  of any search of the repository (for example grep --exclude-dir=example_4). It
  is the deck I am asking you to rebuild, and the point is to rebuild it from
  this description.
- Run a deck from the repository root, in the Python environment where Navigate
  was installed from this repository, with:
      python -m navigate <path to the .nav file> -d ./assumptions
  (`python -m navigate` run from the repository root always uses this
  repository's code; the shorter `navigate` command may point to another copy.)
- A run writes a .log file next to the .nav. The end of the .log has a "Log
  summary" table with the number of warnings and errors. Built as described
  here, this deck runs with no warnings at all: report any you get. `Load DefaultPlot` in the
  .nav DEFINE block also writes the charts to plots/ and plots_analysis/.
  If you cannot run terminal commands, give me the exact command, wait for me to
  paste back the end of the output, and fix whatever it reports.
- To get results as numbers, add `Load DefaultReport` to the .nav DEFINE block.
  The run then also writes plots/<deck name>_report_default.xlsx. Its "Global"
  sheet has one row per year, one ConsumedEnergy column per fuel (GJ per year;
  the fuel name is in the third header row) and the fleet's emissions
  (TotalEquivalentWTW, t CO2e per year).

THE DECK
Build it in a new folder, simulations/user/my_simulation/, with the .nav file
my_simulation.nav and one .inc file per topic in includes/. If that folder
already exists, use my_simulation_2 (then _3, ...) instead, and tell me which.
Write nothing outside that folder: do not change, move or delete any file that
is already in the repository.

THE CASE
Panamax bulk carriers (~80,000 DWT) carrying copper concentrate from San
Antonio, Chile, to Rotterdam via the Panama Canal, 2026 to 2050, yearly steps.
The fleet starts entirely on fuel oil. The model decides which fuel to bunker
and where, how fast to sail, which ships to retrofit or order, and which
efficiency measures to fit. Fuel producers decide where to build plants.

1. Fleet (one Fleet node, "copper_trade")
   - Four ship designs, copied from the library's vessels for this class:
     bulk_carrier_80k_dwt_ice_oil, _ice_methane, _ice_methanol and _ice_ammonia,
     renamed ship_oil, ship_lng, ship_methanol and ship_ammonia.
   - 300 ships in 2026 (INVENTED: about 8 % of the world Panamax fleet), all
     ship_oil, with the library's age distribution for the oil ship
     (Curve("age_dist_bulk_carrier_80k_dwt_oil")) and zero for the other three.
   - No orderbook (leave Orderbook out): the library's is sized for the whole
     world fleet.
   - Trade growth: the library's Forecast("trade_growth_bulk_carrier").
   - Retrofits: the three conversion costs in
     assumptions/defaults/installation/Fleet/bulk_carrier_80k_dwt.inc (oil to
     methanol, oil to ammonia, LNG to ammonia), restated for the new ship names.
   - Speed management: as the same Fleet file sets it (AllowSpeedManagement,
     MaximumSpeedChange).
   - Efficiency measures: the seven library technologies for this class (the
     files ending in _bulk_carrier_panamax in
     assumptions/defaults/installation/Technology/). Start each at the library's
     uptake curve (Curve("uptake_<technology name>")) where one exists. Two
     have none: leave their initial share unset, which means zero (a plain 0
     is rejected, it must be a Curve). Set TechnologyCostOfCapital =
     Variable("cost_of_capital_vessel").

2. Route
   - ROUND_TRIP between San Antonio and Rotterdam, sailing laden out and in
     ballast home (capacity utilisation 1 then 0).
   - 7,600 nautical miles each way (INVENTED: the library has no distances).
   - Speeds and days in port from the library's operational profile for this
     class, assumptions/defaults/installation/Route/operational_profile_bulk_carrier_80k_dwt.inc:
     the most common speed (the one with the largest ConditionDistribution
     share, laden and ballast alike), and days in port per call = (1 - TimeAtSea) x 365 / total
     port calls per year. Show that arithmetic in a comment.
   - Do not use the profile's abstract ports (port_global, port_europe): the two
     ports are your own nodes, san_antonio and rotterdam.

3. Fuels and where they come from
   - Fuel oil and LNG: global commodities. Bunkerable at every port, priced with
     the library's global price forecasts and given the library's upstream (WTT)
     emissions, both as bunker overwrites on the ports. No plant, producer or
     logistics chain for them.
   - E-methanol and e-ammonia: library plants on alkaline electrolysis, on
     dedicated renewable power. One plant of each in the "americas" region
     (Chile) and one of each in "europe". The European ones are Copy Plant of the
     library plants, because the imported ones already carry the library names.
     The library Plant files carry no region or power source: set Region and
     Source on every plant yourself.
   - Bio-methanol: the library's gasification plant, in europe only, on grid power.
   - Give every plant the library's cost of capital for its kind and region,
     as assumptions/modules/installation/default_plant.inc does
     (Forecast("cost_of_capital_plant_electro_americas"), ..._electro_europe,
     ..._bio_europe). Import Plant does not bring it, and a plant without one
     is silently financed at 0 %.
   - All three alternative fuels can be bunkered at both ports.
   - Regions: declare "americas" and "europe" yourself, with the electricity
     cost and grid emission lines of the library's Region files. Do not Import
     them: they also price feedstocks this deck does not have, and the parse
     fails. The production economics (feedstock costs, process capex,
     opex, energy, lifetimes) are the library's, as
     assumptions/modules/installation/default_region.inc sets them for every
     region: restate only the lines for the processes and feedstocks your plants
     use. Within a region, fuel moves by truck at zero cost, with the library's
     truck emissions.
   - Two producers: one owns the four e-fuel plants, one owns the bio-methanol
     plant. Each may build up to Forecast("epc_global_capacity_mid") x
     Forecast("epc_global_share_shipping") a year.
   - Feedstock ceilings: the library's availability x its shipping share x a
     trade share, as set_feed_constraint on the producer that uses it:
       biogenic CO2 (e-methanol), trade share 0.003 (INVENTED)
       gasifiable biomass (bio-methanol), trade share 0.01 (INVENTED)
     The library's shares are for all of shipping; this deck is 300 ships on one
     trade.

4. Bunkering costs (all INVENTED; BunkerLogistics takes plain numbers)
   - Distance from production region to port, nautical miles:
       americas to san_antonio 1,250, americas to rotterdam 7,600,
       europe to rotterdam 540, europe to san_antonio 7,600
   - Transport cost 0.02 USD per ton per nautical mile, for every fuel.
   - Handling cost at the port, USD per ton: fuel oil 8, LNG 15, methanol (both
     kinds) 18, ammonia 25.

5. Regulation: EU ETS and FuelEU Maritime
   Write both Regulation nodes yourself from the library's
   assumptions/defaults/installation/Regulation/eu_ets.inc and fuel_eu.inc:
   keep their settings, global warming potentials and EU default emission
   factors, but only the lines for this deck's five fuels. Change one thing: the
   jurisdiction is Port("rotterdam") instead of port_europe. Both legs then
   count at the inter-jurisdiction fraction (half the voyage), Rotterdam's port
   stays count in full and San Antonio's not at all. Under FuelEU, do not set a
   WTT value for e-methanol or e-ammonia: Navigate then calculates it from their
   production chain.

6. The rest of the DEFINE block
   Load DefaultModelDefinition first and DefaultEmission with the fuels. Load
   DefaultCalibration after your own includes: it sets the decision behaviour
   with wildcards (Fleet "*", ...) that only match nodes already declared.
   Then DefaultReport and DefaultPlot. EVENTS: Load DefaultTimeStepYearly.

PITFALLS (each cost someone time before)
- Do not put two plants making the same fuel in the same region under one
  producer: the bunkering solve stalls for minutes on one year. A normal run of
  this deck takes one to two minutes with the plots; if it runs past ten, stop
  it and tell me.
- A node must exist before another node or a command refers to it. So the
  include order is: fuels, then sources, feedstocks, processes and
  Import Transport "truck", then the regions, then the plants, then the
  producers. Likewise, a wildcard such as Vessel "ship_*" { Route = ... } only
  matches ships already copied, so put it after the Copy Vessel lines.

NUMBERS
Every number must come from assumptions/ and be referenced by name
(Forecast("..."), Curve("..."), Variable("...")), never copied in as a literal.
Where the library itself stores a plain number (the fuel-conversion costs in a
Fleet file, the time at sea in a Route file), copy it with a comment naming the
file it came from. The values marked INVENTED above are the only numbers that
are not from the library: mark each one INVENTED in a comment where it appears
and list them all in the .nav header.

DECK RULES
The .nav DEFINE and EVENTS blocks accept only Include and Load. Every node
declaration, Import and Copy goes in an .inc file that they include.

BEFORE YOU TELL ME IT WORKS
Run it (or have me run it) as above. Report the exit code and the warning and
error counts from the Log summary. Then, from the report, tell me:
- the fleet's well-to-wake emissions in 2026 and in 2050 (kt CO2e per year), and
  summed over 2026-2050;
- the share of alternative fuels (everything but fuel oil and LNG) in the
  energy consumed in 2050;
- the three biggest fuels in 2050.
For comparison, the workshop's own deck for this case gives 5,935 kt in 2026,
3,265 kt in 2050, 127,424 kt in total and 43.3 % alternative fuels in 2050, with
fuel oil, e-ammonia and LNG the three biggest fuels. Say
how close you are, and if you are far off, what in your deck could explain it.

Where to find your simulation, and how to run it again#

Both prompts build the deck in a new folder, simulations/user/my_simulation/ (or my_simulation_2, _3, … if that name is taken), and change nothing else in the repository. The simulations/user/ folder is ignored by git, so your simulation never shows up as a change to the repository.

To run it again, open a terminal in the repository root, in the Python environment where you installed Navigate, and run:

python -m navigate simulations/user/my_simulation/my_simulation.nav -d ./assumptions

It takes one to two minutes. Everything the run writes lands next to the deck, in simulations/user/my_simulation/:

  • my_simulation.log: the run’s log. Its last table, the “Log summary”, counts the warnings and errors.

  • plots/ and plots_analysis/: the charts, among them the fuel consumed and the emissions.

  • plots/my_simulation_report_default.xlsx: the results as numbers. Its “Global” sheet has one row per year, with the energy consumed by fuel and the fleet’s well-to-wake emissions.

To try a change of your own, edit the .inc files in simulations/user/my_simulation/includes/ and run the same command again. Navigate does not delete old charts, so delete plots/ and plots_analysis/ first if you have changed which charts the deck draws.
