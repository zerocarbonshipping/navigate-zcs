Results file#

Every run writes its full results to one Parquet file, <deck>.parquet next to the deck, or to the path given with -o/--results. Open it with Lantern to browse the plots, or read it with any Parquet reader, for example polars, pandas or DuckDB:

import polars as pl

results = pl.read_parquet("my_deck.parquet")
emissions = results.filter(pl.col("attribute") == "total_equivalent_wtw", pl.col("kind") == "global")

Unlike a Report, which writes the properties a deck asks for, the results file holds every result of every node with a profile: the same values the report properties give, and nothing else. Node inputs, such as a fleet’s trade target, are not in it, except the fuel and emission constants the results were converted with, which the metadata holds. A Report remains the way to get a spreadsheet laid out for reading.

Table#

The table is long: one row per series and date. A series whose values are all below 1e-5 in magnitude or missing is left out.

Column

Type

Content

kind

string

global, fleet, vessel, port, plant, producer, regulation or levy

node

string

Node name; empty for global

attribute

string

Result name, e.g. consumed_energy, total_equivalent_wtw, in_fleet

key1

string or missing

First key of a result kept per fuel, fuel type, vessel, …

key2

string or missing

Second key of a result kept per pair, e.g. (fuel, emission)

date

date

Date of the time step

value

float or missing

Value; true/false results are 1 and 0. Missing marks a value that is not set or has no bound, such as a feed constraint without limit

Keys that are identifiers, such as fuel types or energy demand types, are written by name (OIL, PROPULSION, see Appendix: IDs). The result names are those of the report properties in snake case: the report property TotalEquivalentWtw is the attribute total_equivalent_wtw.

Values are per year where the unit says so. The results that count what happened in a time step, newbuilds, scrap, fuel_conversions, newbuild_power, scrapped_power, fuel_converted_power, development and computational_time, are divided by the length of the step in years of 365.25 days, the first step counting as one year. The report gives them per step instead: with yearly time steps the two differ only by the length of the calendar year.

Metadata#

The Parquet key-value metadata holds a JSON document under the key navigate:

Key

Content

schema_version

Version of this layout, currently 2. It changes when a reader has to change.

navigate_version

Navigate version that wrote the file

deck

Name of the deck

created

Time the file was written, UTC, ISO 8601

units

Unit of each attribute, e.g. "consumed_energy": "GJ/year". measure means the unit of the regulation’s measure.

constants

The run’s constants: lower_heating_value per fuel, GJ/t; fuel_type per fuel; liquid_market_fuels; global_warming_potential per emission at emissions_lifetime, years

plant_fuel

The fuel each plant produces

A per-ton result converts to per energy with the heating value of its fuel: a port’s bunker_price divided by lower_heating_value of the fuel in key1 is the price in USD/GJ, and a plant’s investment_cost divided by the heating value of its plant_fuel is the cost in USD/GJ.
