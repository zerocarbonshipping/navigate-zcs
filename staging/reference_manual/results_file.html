Results file#

Every run writes its full results to one Parquet file, <deck>.parquet next to the deck. --name and --output-dir change its name and folder, and a run with --set writes it into the parquets subfolder of that folder. Open it with Lantern to browse the plots, or read it with any Parquet reader, for example polars, pandas or DuckDB:

import polars as pl

results = pl.read_parquet("my_deck.parquet")
emissions = results.filter(pl.col("attribute") == "total_equivalent_wtw", pl.col("kind") == "global")

The results file holds every result of every node that holds results, and nothing else. Node inputs, such as a fleet’s trade target, are not in it, except the fuel and emission constants the results were converted with, which the metadata holds.

Table#

The table is long: one row per series and date. A series whose values are all below 1e-5 in magnitude or missing is left out.

Column

Type

Content

kind

string

global, fleet, vessel, port, plant, producer, regulation or levy

node

string

Node name; empty for global

attribute

string

Result name, e.g. consumed_energy, total_equivalent_wtw, in_fleet

key1

string or missing

First key of a result kept per fuel, fuel type, vessel, …

key2

string or missing

Second key of a result kept per pair, e.g. (fuel, emission)

date

date

Date of the time step

value

32-bit float or missing

Value, to about seven significant digits; true/false results are 1 and 0. Missing marks a value that is not set or has no bound, such as a feed constraint without limit

Keys that are identifiers, such as fuel types or energy demand types, are written by name (OIL, PROPULSION, see Appendix: IDs). The attributes of each kind are listed under Results.

Values are per year where the unit says so. The results that count what happened in a time step, newbuilds, scrap, fuel_conversions, newbuild_power, scrapped_power, fuel_converted_power, development and computational_time, are divided by the length of the step in years of 365.25 days, the first step counting as one year.

Metadata#

The Parquet key-value metadata holds a JSON document under the key navigate:

Key

Content

schema_version

Version of this layout, currently 1. It changes when a reader has to change.

navigate_version

Navigate version that wrote the file

deck

Name of the run: the deck’s file name without extension, or the name given with --name

created

Time the file was written, UTC, ISO 8601

params

The placeholder values given with --set, as text, by name; empty without any

units

Unit of each attribute, e.g. "consumed_energy": "GJ/year". measure means the unit of the regulation’s measure.

constants

The run’s constants: lower_heating_value per fuel, GJ/t; fuel_type per fuel; liquid_market_fuels; global_warming_potential per emission at emissions_lifetime, years

plant_fuel

The fuel each plant produces

A per-ton result converts to per energy with the heating value of its fuel: a port’s bunker_price divided by lower_heating_value of the fuel in key1 is the price in USD/GJ, and a plant’s investment_cost divided by the heating value of its plant_fuel is the cost in USD/GJ.

Results#

This section lists every series a results file can hold. A series is one kind, node, attribute, key1 and key2, and has a row for every date of the run:

consumed = results.filter(
    pl.col("kind") == "fleet",
    pl.col("node") == "bulk_carrier",
    pl.col("attribute") == "consumed_energy",
    pl.col("key1") == "fossil_fuel_oil",
)

The tables name a series by kind.attribute, the way Lantern’s plot catalogue does: fleet.consumed_energy stands for the series with kind fleet and attribute consumed_energy, one per fleet and fuel. A row that names several kinds describes the attribute in each of them.

global holds one series per attribute and key, with no node. Every other kind holds one per node of that type in the run. That means every Fleet, Vessel, Port, Plant, Producer, Regulation and Levy the deck uses, including those it loads from the assumptions library.

A series is written only when some date of it holds a value of at least 1e-5 in magnitude. The Present when column says what a run needs for that. If the run doesn’t meet it, the series is left out of the file, so filtering for it returns no rows. A series that is in the file can still be missing at some dates, as that column says.

Some rules hold throughout:

  • Vessel results describe one ship. A vessel series is one ship of that type, regulation results per vessel included. The fleet sums its vessel types, each weighted by its existing_vessels, and global sums the fleets. Speeds, rates, savings, shares and intensities are not summed: each kind computes its own from its totals.

  • The first date sets up the run. The first time step starts the fleets and production and runs the bunkering. Newbuilds, scrapping, fuel conversions, technology installation, speed management and plant development start at the second date. Their counts are 0 at the first date, and the results they write are missing there.

  • The keys hold names. The Keys column names what key1 holds and, after the comma, key2:

    • fuel, emission, vessel, technology, regulation and levy are node names.

    • feed is a Feedstock or Process name.

    • fuel type is a FuelTypeID. On a vessel it is the vessel’s primary fuel type, so installed_power keyed OIL is the power of the oil-fuelled vessels.

    • energy demand is an EnergyDemandID. In port it is only ELECTRICAL or HEAT.

    • timing is a TimingID.
